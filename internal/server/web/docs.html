Strix 使用教程

开箱即用的轻量级分布式运维监控系统 · 服务端 + 采集端协同工作，可监控数千台主机

三分钟跑起来

下载二进制或使用 Docker Compose 启动服务端 → 浏览器打开控制台并登录 → 在「监控 → 添加主机」复制一条命令到目标主机执行 → 主机自动出现在列表中。 全程不需要 MySQL、不需要 JDK、不需要模板与脚本。

产品概述

Strix 是一款开箱即用的轻量级分布式运维监控系统，主打极简部署、自动化运行、零模板零脚本。 服务端与采集端协同工作，可监控数千台主机。

核心监控指标

Docker Compose 部署推荐

最省事的方式。整个系统一个容器、一个数据目录，备份就是拷一个目录。

1. 准备目录

mkdir -p /opt/strix/data
cd /opt/strix

2. 编写 docker-compose.yml

services:
  strix:
    image: strix/strix:latest
    container_name: strix
    restart: unless-stopped
    ports:
      - "9999:9999"
    volumes:
      # SQLite 数据库所在目录，必须挂载，否则容器重建后数据全丢
      - ./data:/opt/strix/data
      # 采集端发布物缓存目录（用于一键安装采集端），可选
      - ./releases:/opt/strix/releases
    environment:
      # 监听地址：保持默认，不要写成 127.0.0.1，否则其他主机接不进来
      STRIX_ADDR: ":9999"
      # SQLite 文件路径
      STRIX_DB: "/opt/strix/data/strix.db"
      # 采集端通信密钥，两端必须一致，建议部署后立即修改
      STRIX_TOKEN: "请改成你自己的密钥"
      # 控制台初始账号密码，仅首次启动生效
      STRIX_ADMIN_USER: "admin"
      STRIX_ADMIN_PASS: "请改成强密码"
      # 对外访问地址，反向代理 / 端口映射场景务必显式指定
      # 安装脚本与采集端升级下载都用它拼装绝对地址
      STRIX_PUBLIC_URL: "http://192.168.1.10:9999"
      # 历史数据保留天数，0 表示永久保留
      STRIX_RETENTION: "30"
      # 超过该秒数未上报判定主机离线
      STRIX_OFFLINE_SEC: "180"
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:9999/"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 10s
STRIX_PUBLIC_URL 最容易填错 填了 127.0.0.1 或 localhost 时， 在服务端本机生成的安装命令拷到其他主机执行必然失败。 必须是其他主机能访问到的地址。

3. 启动

docker compose up -d
docker compose logs -f --tail=100

看到 控制台访问地址：http://…:9999 即启动成功，浏览器打开该地址，用上面设置的账号登录。

4. 常用运维命令

docker compose restart strix   # 重启
docker compose stop strix      # 停止
docker compose up -d                # 启动
docker compose logs -f              # 跟踪日志
docker compose pull && docker compose up -d   # 拉新版并重建

1Panel 部署

  1. 安装 Docker 应用

    在 1Panel 左侧「应用商店」搜索并安装 Docker（若已安装可跳过）。

  2. 新建容器

    「容器」→「创建容器」，填写：

    字段值
    名称strix
    镜像strix/strix:latest
    重启策略始终重启
    端口映射主机 9999 → 容器 9999
    文件夹新建 /opt/strix/data
    挂载/opt/strix/data → /opt/strix/data（读写）
    环境变量见下方表格
  3. 设置环境变量
    变量建议值
    STRIX_TOKEN自定义强密钥
    STRIX_ADMIN_USERadmin
    STRIX_ADMIN_PASS自定义强密码
    STRIX_PUBLIC_URLhttp://服务器IP:9999
  4. 配置反向代理（可选）

    「网站」→「创建网站 → 反向代理」，域名如 monitor.example.com， 代理地址填 http://127.0.0.1:9999。 配了反向代理后务必把 STRIX_PUBLIC_URL 改成 https://monitor.example.com。

  5. 防火墙放行

    服务器防火墙与云安全组都要放行 9999/TCP（或反向代理的 443）。

宝塔面板部署

  1. 安装 Docker 管理器

    「软件商店」→ 搜索 Docker 管理器 → 安装。

  2. 添加容器

    「Docker」→「容器管理」→「添加容器」，镜像填 strix/strix:latest， 端口映射 9999:9999，目录挂载 /opt/strix/data 到 /opt/strix/data。

    同 1Panel，注意 STRIX_PUBLIC_URL 要填对外可达地址。

  4. 反向代理

    「网站」→ 添加站点 → 反向代理到 http://127.0.0.1:9999。

  5. 放行端口

    「安全」→ 添加放行端口 9999。

Linux 二进制部署

不想用容器时，直接跑二进制。服务端只需要 glibc 与一个可写目录。

1. 下载并安装

mkdir -p /opt/strix/data && cd /opt/strix
curl -fLo strix-server https://github.com/sangxi/strix/releases/latest/download/strix-server-linux-amd64
curl -fLo strix-agent   https://github.com/sangxi/strix/releases/latest/download/strix-agent-linux-amd64
chmod +x strix-server strix-agent
./strix-server -version

2. 前台试跑

./strix-server \
  -addr :9999 \
  -db ./data/strix.db \
  -token '你的通信密钥' \
  -user admin -pass '你的控制台密码' \
  -public-url 'http://192.168.1.10:9999'

确认能访问 http://服务器IP:9999 后再做成systemd 服务。

3. 注册为 systemd 服务

sudo tee /etc/systemd/system/strix.service >/dev/null <<'EOF'
[Unit]
Description=Strix 运维监控服务端
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/strix
ExecStart=/opt/strix/strix-server -addr :9999 -db /opt/strix/data/strix.db -token 你的通信密钥 -user admin -pass 你的控制台密码 -public-url http://192.168.1.10:9999
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now strix
sudo systemctl status strix --no-pager
把密钥写进 unit 文件要注意 -token 会以明文出现在 /etc/systemd/system/strix.service 中。 该文件默认只有 root 可读，一般可以接受；若安全要求更高，改用环境文件： EnvironmentFile=/etc/strix/strix.env（权限设为 600）。

4. 常用命令

systemctl restart strix
journalctl -u strix -f          # 实时日志
journalctl -u strix --since today

$trigger= New-ScheduledTaskTrigger -AtStartup

  -Principal $principal -Force

Get-ScheduledTaskInfo -TaskName strix-agent | Select-Object LastRunTime,LastTaskResult

文件挂载清单

部署前按这张表核对，避免出现「重启后数据全丢」这类事故。

目录结构

/opt/strix/
├── strix-server          # 服务端二进制（容器内为镜像自带，不用挂）
├── strix-agent           # 采集端二进制（仅手工部署采集端时需要）
├── data/
│   ├── strix.db# SQLite 主库 必须挂载
│   ├── strix.db-wal      # WAL 日志，与主库同目录
│   └── strix.db-shm      # 共享内存索引，与主库同目录
├── releases/                  # 采集端发布物缓存（可选，用于一键安装采集端）
│   └── strix-agent-linux-amd64
└── strix-file-baseline.json   # 文件防篡改基线（仅采集端，产生在采集端本机）

挂载对照表

宿主机路径容器内路径读写必需性不挂的后果
/opt/strix/data /opt/strix/data 读写 必需 容器重建后所有历史指标、告警、资产、账号全部丢失
/opt/strix/releases /opt/strix/releases 读写 可选 一键安装采集端时提示「服务端尚未发布 xx/xx 的采集端版本」
— /etc/localtime 只读 建议 容器内时区变成 UTC，告警时间与主机时间差8 小时
/opt/strix/strix-file-baseline.json — 读写 仅采集端 采集端重启后文件防篡改基线丢失，首次运行会重建基线
最关键的一条 data 目录必须挂载。SQLite 数据库是整个系统唯一的状态存储， 不挂载等于每次重建容器都从零开始。

时区配置

services:
  strix:
    environment:
      TZ: "Asia/Shanghai"
    volumes:
      - /etc/localtime:/etc/localtime:ro

一键安装采集端

  1. 控制台生成命令

    登录控制台 → 左侧「监控」→「添加主机」→ 选择系统与架构、填写主机名 → 复制命令。

  2. 确认目标平台已发布

    页面会提前校验该「系统 + 架构」是否已有可下发的采集端版本。 平台是按系统 + 架构分别发布的， linux/amd64 发布过不等于 linux/arm64 就能装。

  3. 在目标主机执行

    Linux / macOS：

    curl -fsSL "http://服务端IP:9999/install.sh?wgToken=密钥MD5&name=web-01" | sudo bash

    Windows（管理员 PowerShell，单行）：

    Invoke-Expression (Invoke-WebRequest -UseBasicParsing "http://服务端IP:9999/install.ps1?wgToken=密钥MD5&name=win-01").Content
  4. 脚本自动完成的事

    识别系统与架构 → 查询平台下发版本 → 下载二进制 → 校验 SHA256 → 拉取平台下发的运行配置 → 注册开机自启的系统服务 （Linux 用 systemd、macOS 用 launchd、Windows 用计划任务）。

  5. 确认上线

    主机自动出现在「主机监控」列表中，默认每分钟上报一次。

命令里为什么只有一个 MD5 安装命令只带 -server / -token-hash / -name 三个必要参数。 通信密钥以 MD5 指纹形式下发，命令行历史与 systemd 单元文件里都不会留下明文口令。 其余运行配置（上报间隔、执行指令开关、更新策略等）全部由平台统一下发并热更新， 改配置不需要登录任何一台主机。

手工部署采集端

不便执行脚本的场景（安全管控、离线环境）可以手工安装。

Linux（systemd）

sudo install -m 0755 strix-agent /usr/local/bin/
sudo tee /etc/systemd/system/strix-agent.service >/dev/null <<'EOF'
[Unit]
Description=Strix 采集端
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/strix-agent -server http://服务端IP:9999 -token 你的通信密钥 -name 本机名
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now strix-agent
sudo systemctl status strix-agent --no-pager
journalctl -u strix-agent -f

macOS（launchd）

sudo install -m 0755 strix-agent /usr/local/bin/
sudo tee /Library/LaunchDaemons/strix-agent.plist >/dev/null <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>strix-agent</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/local/bin/strix-agent</string>
    <string>-server</string><string>http://服务端IP:9999</string>
    <string>-token</string><string>你的通信密钥</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/var/log/strix-agent.log</string>
  <key>StandardErrorPath</key><string>/var/log/strix-agent.log</string>
</dict>
</plist>
EOF

sudo launchctl load -w /Library/LaunchDaemons/strix-agent.plist

卸载

# Linux
sudo systemctl disable --now strix-agent
sudo rm -f /etc/systemd/system/strix-agent.service /usr/local/bin/strix-agent

# macOS
sudo launchctl unload /Library/LaunchDaemons/strix-agent.plist
sudo rm -f /Library/LaunchDaemons/strix-agent.plist /usr/local/bin/strix-agent

# Windows
Unregister-ScheduledTask -TaskName strix-agent -Confirm:$false

主机记录会保留，历史数据按服务端保留天数自动清理。

容器内采集宿主主机

需要监控 Docker 所在宿主机的物理指标时，把宿主机根目录挂进容器。

services:
  strix-agent:
    image: strix/strix-agent:latest
    container_name: strix-agent
    restart: unless-stopped
    pid: host
    network_mode: host
    volumes:
      # 只读挂载宿主机根目录，让采集端看到真实的 /proc、/sys
      - /:/host:ro,rslave
    environment:
      - TZ=Asia/Shanghai
    command:
      - -server=http://服务端IP:9999
      - -token=你的通信密钥
      - -name=容器宿主机名
只读挂载 ro 一定要加。采集端只需要读 /proc、/sys， 不需要也不应该能修改宿主机文件。

授权中心通信

平台默认已接入内置授权中心（地址已内置在程序里，无需手动填写），每次同步做四件事：

  1. 拉取并校验导入授权码（授权中心签发后最长一个间隔内生效）
  2. 下载各平台采集端发布物到本地 releases/，设为下发版本
  3. 检测到服务端自身有新版本时自动下载、校验 SHA256、替换二进制；就位后按 -hub-restart 决定是否自动重启生效（默认自动）
  4. 把采集端升级结果回执授权中心
采集端发布物按平台逐个补拉（1.1.1 起） 授权系统按请求的 os/arch 返回对应发布物，因此服务端会对 linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64 共 5 个平台逐个查询补拉，彻底修复「Linux 服务端装不上 Windows 采集端 / 提示『授权系统尚未发布该平台』」的问题。 除当前平台外的其它平台补拉改到后台执行，避免「立即检查更新」被网关超时（HTTP 524）拖死。 授权端下载接口只认 ?token= 查询串鉴权（不认 X-Opsm-Hub-Token 请求头），平台下载时自动带上。
采集端不直接访问授权中心 内网采集端只需要能连到监控端的 9999 端口，不需要为每台被监控主机开通任何出网策略。 只有监控端需要访问公网。
网关拦截是最常见的问题 若授权中心前置了开启 Bot 防护的 CDN（Cloudflare 等）， 程序客户端会被人机校验挡下并返回 403，页面上会明确提示这一点。 处理方式是在网关上为 /api/* 路径放行，或改用不挂代理的接口子域， 或直接加 -hub "" 转为完全离线模式（功能不受影响）。

控制台「在线升级」「授权购买」页不再展示授权中心域名，也去掉了跳转到授权站的按钮（1.1.4 起）。

主机重命名与删除 1.1.5 起

「主机监控」列表里每台主机行的操作区有 重命名 与 删除 两个按钮，仅管理员可见。 主机名支持中文、日文等任意语言文字（1.1.5 起修复了中文名被一键安装脚本清成一串 - 的问题）。

重命名

主机名由采集端的 -name 启动参数决定，平台无法远端修改已部署主机上的服务参数。 因此平台侧的做法是：把该主机名下的全部数据迁移到新名字，并登记「旧名 → 新名」映射。 迁移范围包括指标、告警、系统事件、目录归属、采集端配置、监控项里的「作用主机」，以及资产管理中的「关联监控主机」。

改完不用重装采集端 采集端仍会按自身配置的旧名上报，平台自动归到新名字下，所以改名后不会冒出第二台「旧名」主机。 什么时候想彻底换掉采集端的名字，重装一次（1.1.5 起的安装脚本）即可。

删除

删除会连同该主机的全部历史数据一起清理，不可撤销。 注意：若该主机的采集端仍在运行，它会在下次上报时被重新发现—— 有活着的采集端就是在线主机。要让它彻底不再出现，请先在目标主机上停用或卸载采集端 （sudo systemctl disable --now strix-agent）。

1.1.6 之前有个缺陷：大屏刚打开时图表正常，约 10 秒后（正好一个自动刷新周期） KPI 数字仍在跳动、所有图表面板却一起变成空白。原因是每次刷新都会重建整块页面 DOM，而 ECharts 实例还绑在被移除的旧容器上，新数据被画到了已经不在页面里的 画布上。1.1.6 起改为「只要容器换了就重建实例」，已彻底修复——升级到 1.1.6 及以上版本即可，无需改动任何配置。

备份与恢复

全部状态都在一个 SQLite 文件里，备份就是拷文件。

在线热备份（推荐）

直接复制 strix.db 可能在写入过程中拿到不一致的快照。 用 SQLite 自带的备份命令更稳妥：

# 需要容器内有 sqlite3，或用官方镜像临时起一个
sqlite3 /opt/strix/data/strix.db ".backup '/opt/strix/backup/strix-$(date +%F).db'"

停机冷备份（最简单可靠）

docker compose stop strix
tar czf /backup/strix-$(date +%F).tar.gz -C /opt/strix data
docker compose start strix

恢复

docker compose stop strix
tar xzf /backup/strix-2026-10-11.tar.gz -C /opt/strix
docker compose start strix

建议的定时备份

# 每天 03:17 冷备一次，保留 14 天
17 3 * * * cd /opt/strix && \
  tar czf /backup/strix-$(date +\%F).tar.gz data && \
  find /backup -name 'strix-*.tar.gz' -mtime +14 -delete
备份一定要演练恢复 备份文件存在不等于能恢复。至少每季度在测试环境完整恢复一次。

升级与回滚

服务端升级

# Docker
docker compose pull && docker compose up -d

# 二进制（手工替换，务必按下面 5 步）
sudo systemctl stop strix
sudo cp /opt/strix/strix-server /opt/strix/strix-server.bak
sudo cp 新版/strix-server /opt/strix/strix-server
sudo systemctl start strix

手工替换二进制升级步骤

  1. 备份旧二进制

    sudo cp /opt/strix/strix-server /opt/strix/strix-server.bak

  2. 清理待生效标记文件

    sudo rm -f /opt/strix/.strix-server.pending

    不清掉的话，启动时程序会认为「上次升级尚未生效」而回滚到 .bak，表现为「换了二进制又变回旧版」。这一步最关键。

  3. 替换二进制并赋权

    sudo cp 新版/strix-server /opt/strix/strix-server && sudo chmod +x /opt/strix/strix-server

  4. 重启服务

    sudo systemctl restart strix

  5. 校验版本

    /opt/strix/strix-server -version

前端（HTML / JS / CSS）通过 //go:embed all:web 编译进同一个二进制，因此升级只需替换这一个二进制文件，无需另行部署静态资源。

平台自升级与自动重启（1.1.3 起）

服务端自身在平台升级换完二进制后会自动重启使新版本生效，不再需要人工 systemctl restart：

  • systemd（unit 用 Restart=always）：进程退出后由 systemd 用新版本拉起
  • Docker Compose（restart: unless-stopped）：容器 PID 1 退出后由 compose 重启容器
  • 手工 nohup 启动：自行拉起同参数的新进程后退出；端口被占用会重试，最多 20 秒
  • 新版本启动失败：下次启动时自动回滚到 .bak

行为由 -hub-restart 控制：auto（默认）自动重启生效；off 只替换文件不重启，需人工重启。启动时端口被占用会自动重试最多 20 秒，覆盖「新进程先起、旧进程后退」的交接窗口。

升级后清一次前端缓存（1.1.2 起） 内嵌前端资源统一带 Cache-Control: no-cache，升级后浏览器与反向代理不会再用旧前端。 若页面表现异常，仍建议 Ctrl+F5 强制刷新一次。

采集端自动升级

采集端按平台配置的检查间隔（默认 30 分钟）查询版本，发现新版本会自行 下载 → 校验 SHA256 → 替换二进制 → 重启，全程不需要登录目标主机。

  • 由 systemd / launchd 托管时直接退出交给服务管理器拉起，不会同时跑两个进程
  • 替换走「旧文件改名 → 新文件落位」的原子流程，Windows 上正在运行的 exe 也能安全替换
  • 校验不过直接中止并保留原进程；替换失败会回滚旧文件

回滚

采集端发布物按「系统 + 架构」分别登记，每个平台可保留多个版本， 其中一个是下发版本——改它就是灰度或回滚。 在控制台「在线升级」页操作即可。

排查顺序

  1. 看服务端日志：docker compose logs --tail=200 或 journalctl -u strix -n 200
  2. 看采集端日志：Linux journalctl -u strix-agent -n 200， Windows Get-ScheduledTaskInfo -TaskName strix-agent
  3. 在目标主机自测连通性：curl http://服务端IP:9999/
  4. 自测授权中心：curl -o /dev/null -w '%{http_code}' "https://<你的授权中心地址>/api/v1/check?token=xxx"，期望 200
  5. 看控制台「操作审计」，确认配置改动是否生效
  6. 看控制台「系统设置 → 机器人推送 / 邮件」，确认告警通道是否可用（可点测试）
